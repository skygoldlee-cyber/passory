## 0. 이 문서의 사용법

- **본 문서 단독으로 인도**한다. 별도 참조 문서·코드 경로·프로젝트 전용 용어를 포함하지 않도록 작성됐다.
- 각 요구사항의 **[근거]** 는 실제 장애·실측에서 나온 것으로, 수주사의 임의 변경을 막는 근거이다.
- 우선순위: **M**(필수 — 검수 탈락 사유) · **S**(권장 — 미충족 시 사유서 필요) · **C**(선택).
- 수주사는 본 문서의 요구사항을 **프로젝트 전용 문서로 변환**해 승인받는다(§8 산출물 의무 참조). 본 문서는 계약상 검수 기준으로 기능한다.
- 본 문서의 요구사항 ID(`BP-`·`NAV-`·`LAY-`·`CM-`·`ST-`·`PW-`·`TH-`·`AX-`·`PF-`)는 **패키지 범위 전용**이다 — 원청 저장소의 동일 접두사 ID와 의미가 다르다(예: 패키지 `PF-01`=성능 지표 ↔ 원청 `PF-01`=MD 파싱). 수주사 산출물의 SPEC ID는 프로젝트 고유 접두사 체계를 사용한다.

## 3. 내비게이션 계약 (M)

| # | 요구사항 | 근거 |
|---|----------|------|
| NAV-01 | 3단계 적응형 네비게이션: PC=좌측 사이드바, 태블릿=상단 sticky 바(항목 가로 스크롤), 모바일=하단 고정 탭바(핵심 5개 이하) + 초과 항목은 "더보기" 하단 시트(`role="dialog"`). **한 번에 하나의 네비게이션만 노출** | 탭이 늘어날 때 가로 스크롤보다 "5탭+더보기"가 발견성·터치 안정성에 유리 |
| NAV-02 | 하단 탭바는 `env(safe-area-inset-bottom)`을 반영해 홈 인디케이터와 겹치지 않는다. 콘텐츠 영역에도 같은 만큼의 `padding-bottom` + `scroll-padding-bottom`을 둔다 | 탭바에 가려지는 콘텐츠·포커스 요소 실사고 있음 |
| NAV-03 | 현재 위치는 아이콘 + 라벨 + 색으로 표시한다(색만으로 구분 금지). 활성 탭은 `aria-current="page"` | 접근성·인지 |
| NAV-04 | 뷰 전환은 URL 해시(`#/슬러그`)에 반영되어 뒤로가기·새로고침·공유가 동작한다. 모달·오버레이도 뒤로가기로 닫힌다 | SPA에서 뒤로가기 미지원 시 Android/PWA 뒤로가기가 앱 종료로 이어짐 |
| NAV-05 | 뷰 복귀(내비 클릭·뒤로가기)는 이전 스크롤을 복원하고, **액션 딥링크(버튼으로 여는 문서형 화면)는 맨 위로 연다** | 복귀와 신규 진입의 기대 동작이 다름 — 딥링크가 이전 스크롤을 복원하면 중간에서 열려 맥락 상실 |
| NAV-06 | 헤더는 `position: sticky` + 반투명 배경 + `backdrop-filter`. 단, 부모가 스크롤 컨테이너일 때만 작동하므로 스크롤 소유 구조를 먼저 확정한다 | body 스크롤 구조와 혼용 시 무력화 |
| NAV-07 | sticky 헤더에 `overflow: hidden` 금지 — 헤더 아래로 펼쳐지는 드롭다운이 잘린다. 넘침 제어는 `min-width:0`+말줄임+`flex-shrink:0`으로 | 실사고 |

## 4. 기기별 배치 계약 — 화면 작성 양식

수주사는 **앱의 화면마다** 아래 3열 매트릭스를 작성해 승인받는다. 아래는 양식의 예시(읽기 화면).

| 항목 | 모바일 | 태블릿 | PC |
|---|---|---|---|
| 배치 | 본문 1단, 크롬은 오버레이 | 본문 1단, 크롬 오버레이 | 본문 + 고정 목차 패널 |
| 목차 | 좌측 드로어(엣지 핸들+백드롭) | 좌측 드로어 | 상시 사이드 패널 |
| 보조 패널 | 하단 시트 | 우측 슬라이드 | 고정 패널 |

공통 규칙:

| # | 요구사항 | 우선 | 근거 |
|---|----------|------|------|
| LAY-01 | 읽기·뷰어처럼 본문이 목적인 화면의 크롬(툴바·필터)은 **오버레이 배치 + 스크롤 다운 시 자동 숨김, 업 시 복귀**. 인플로우 배치 금지 | M | 인플로우 크롬은 본문 높이를 영구 잠식(실측 본문 가시 영역 63%→89% 개선 사례). 오버레이 시 콘텐츠에 `padding-top`=크롬 높이를 줘 첫 화면이 묻히지 않게 함 |
| LAY-02 | 각 스크롤 영역의 소유자를 명시한다(페이지 스크롤 vs 컨테이너 스크롤). 오버레이·드로어의 오버플로가 페이지 스크롤로 전파되지 않는다 | M | 오버레이 넘침이 뷰 전체를 밀어내는 실사고 |
| LAY-03 | 표는 모바일에서 가로 스크롤 컨테이너(`width:max-content; min-width:100%`)에 넣는다 | M | — |
| LAY-04 | 하단 `position:fixed` 요소(배너·토스트·플로팅 버튼)는 모바일에서 `calc(탭바 높이 + safe-area)` 이상 위에 띄운다 | M | back-to-top이 탭바에 완전히 가려진 실사고 |

## 9. 수주사 산출물 의무

수주사는 다음 문서를 **본 패키지 양식으로** 작성·납품한다:

| 산출물 | 양식 | 내용 |
|--------|------|------|
| 화면 지도(Screen Map) | 표 | 전체 화면의 `화면명 ↔ view id ↔ URL 해시 ↔ 내비 위치 ↔ 요구사항 ID` + 비뷰 오버레이(모달·시트·토스트) 목록 + 화면별 상태 분기 |
| 사용자 흐름(User Flow) | Mermaid `flowchart` | 핵심 여정(기동·핵심 작업 루프·오류 분기)을 진입 조건·분기·종료 조건·상태 저장 지점으로 기술 |
| 기기별 배치 계약 | 본 문서 §4 매트릭스 | 화면마다 모바일/태블릿/PC 3열 배치 + 크롬·스크롤 소유자 명시 |
| 요구사항 명세(SPEC) | ID 표 | 기능·UI/UX 요구사항에 고유 ID 부여 — **구현·테스트·검수가 ID로 추적**되도록 |
| 검증 계획 | 체크리스트 | §10 뷰포트·체크리스트 기준으로 각 항목의 검증 수단(자동 E2E / 수동) 명시 |

## 10. 납품 검수 기준

### 10.1 검수 뷰포트

| 구분 | 크기(px) | 대표 용도 |
|---|---|---|
| 모바일 | 412 × 915 (또는 실기기 Pixel급) | 하단 탭바 배치 |
| 모바일 최소 | 360 × 800 | 가로 오버플로·터치 영역 |
| 최소 지원 폭 | 320 × 568 | BP-03 가로 스크롤 부재 검증 |
| 태블릿 | 834 × 1112 | 상단 바 배치 |
| PC | 1280 × 720 / 1440 × 900 | 사이드바 배치 |

> 자동화(E2E)로 커버되는 항목: 가로 오버플로·레이아웃 계측·키보드·axe 스캔·테마 전환. **실기기 수동 확인이 필수인 항목**: PWA 설치 프롬프트·safe-area(노치·홈 인디케이터)·주소창 동적 높이(`dvh`)·실제 터치 제스처.
>
> 관계: 본 표는 수동 검수를 포함한 **검수 계약**이다. 원청 SPEC §4.10.5의 3종(데스크톱·모바일·태블릿)은 Playwright 자동화 프로젝트 커버리지로 범위가 다르다 — 검수는 본 표를 기준으로 한다.

### 10.2 검수 체크리스트

- [ ] 모든 검수 뷰포트에서 가로 스크롤이 생기지 않는다
- [ ] 내비게이션이 대역별 정확한 형태로 1개만 노출된다
- [ ] URL 해시로 딥링크·뒤로가기·새로고침이 동작한다
- [ ] 뷰 복귀는 스크롤 복원, 액션 딥링크는 맨 위 오픈
- [ ] 진행 중 작업·읽기 위치가 재실행 후 복원된다
- [ ] 라이트·다크 양쪽에서 axe critical/serious 0건
- [ ] 터치 타겟 44px·입력 16px·`:active` 피드백이 적용된다
- [ ] 오프라인·재방문 시 캐시된 핵심 기능이 동작한다
- [ ] iOS 홈 화면 실행 시 하단 UI가 safe-area를 반영한다
- [ ] §9 산출물 5종이 요구사항 ID로 추적 가능하게 납품됐다

### 10.3 알려진 함정 (검수 시 참고)

| 함정 | 원인 | 확인법 |
|------|------|--------|
| 다크모드에서 카드가 흰 배경+회색 글자 | CSS 변수 미정의 → 폴백 상시 적용 | 변수 정의 여부 정적 검사 + 다크 테마 실측 |
| 모바일에서 버튼이 아예 안 보임 | 조상이 모바일 미디어쿼리에서 `display:none` | 전 대역 가시성 확인 |
| 애니메이션 후 fixed 요소 위치 붕괴 | `animation: ... forwards`가 transform을 잔류시켜 조상을 containing block화 | fill-mode 잔류 transform 금지 — 완료 시 클래스 해제 |
| flex 높이 체인 단절로 내부 스크롤 소멸 | 특정 대역에서 `height:auto`가 flex 경계를 끊음 | 대역별 스크롤 컨테이너 실측(`scrollHeight > clientHeight`) |
| 가장자리 회색 띠 등 "앱 결함" 신고 | OS 기능(엣지 패널)·타 앱 오버레이 | 코드 수정 전 기기 기능 확인 — 모든 화면·고정 위치면 OS 의심 |

### 10.4 검수 운영 기준 (수주사 질의 회신 확정분)

**지원 환경 하한**

- iOS Safari 15.4+ · Chrome/Edge 105+ · Samsung Internet 20+ (데스크톱·모바일 공통)
- 산정 근거: `:has()` 선택자와 `dvh` 단위의 지원 시작점이 실질 하한. `backdrop-filter`·`overscroll-behavior`·`env(safe-area-inset-*)`는 점진 향상 또는 폴백 처리 — 하한 산정 제외. Firefox는 대상 외

**실기기 수동 검수**

- 대상 기종(대표 조합 2종): ① iOS Safari — 노치/Dynamic Island 기기 (safe-area·standalone·동적 주소창) ② Android Chrome — 제스처 내비게이션 기기 (설치 프롬프트·탭 바 겹침·SW 업데이트 토스트)
- 수행 주체: 수주사 1차 검수 — **기기 모델·OS·브라우저 버전 + 스크린샷 증거 제출**, 원청 최종 확인
- 자동화 불가 항목은 면제 표(ID·사유·수동 절차·증거·재평가 시점)에 등록한 것만 유효

**성능 지표 측정 조건 (PF-01)**

| 항목 | 조건 |
|------|------|
| 도구 | Lighthouse 모바일 프리셋 (lab 측정 — 필드/RUM 데이터는 수집 수단 없어 대상 외) |
| 스로틀링 | CPU 4x · Slow 4G |
| 대상 화면 | 대시보드 초기 로드(cold) · 교재리더 챕터 오픈 — 최대 트래픽 경로 2개 |
| 판정 | 각 화면 3회 측정 **중앙값**이 목표 이내 |

**접근성 검수 범위**

- 기준 레벨: **WCAG 2.1 AA** (axe 태그 `wcag2a/2aa/21a/21aa`)
- 자동 스캔 대상: 대표 뷰(대시보드·플래시카드·설정 패널 오픈) × 라이트+다크 테마 — critical+serious 0건 게이트, moderate/minor는 보고만
- 오탐 예외는 근거(rule·selector·실측)가 문서화된 목록으로만 허용
- 스크린리더는 자동화 불가 — iOS VoiceOver로 핵심 시나리오(뷰 이동·카드 뒤집기·모달 열기/닫기) 수동 수행, 면제 표에 등록

**산출물 승인 절차**

- 승인 창구: 원청 단일 창구 — 회신 기한은 제출일로부터 **영업일 3일**, 기한 내 이견 없으면 제출안 기준으로 진행
- 승인 전 착수: 과업 범위 확정(A 항목 회신) 전까지 구현 착수 불가 — 승인 전에는 환경 세팅·읽기 전용 검토만 허용

**검수·재검수 및 S 등급 미충족 처리**

- 검수 횟수: 1차 검수 + 재검수 1회 (총 2회) — 재검수 미충족 항목은 원청 판정으로 등급 확정 또는 제외 처리
- S 등급 미충족 시 사유서 4요소: **① 항목 ID ② 미충족 사유 ③ 영향 범위 ④ 재평가 시점** — 구두·주석 합의는 인정하지 않으며 검수 보고서에 누적 표기
