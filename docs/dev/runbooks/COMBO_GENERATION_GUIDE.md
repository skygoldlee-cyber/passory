# 복수정답형(ㄱㄴㄷ 조합) 문항 생성 가이드

> `tools/build/build_combo_drills.js` + `tools/build/ref_statements.js`가
> 문제은행 객관식과 참조자료 원문을 **복수정답형 드릴 문항**으로 변환·생성하는
> 전체 과정을 설명합니다. 스키마 자체는 `QUESTION_SCHEMA_DESIGN.md` §6 참조.
> **관련 SPEC ID**: `DR-02~07` (복수정답형 드릴) · `BP-*` (빌드 파이프라인)
> **문서 ID**: DOC-RBK-02
> **범위**: platform · 판본: none

## 1. 개요

복수정답형은 "다음 중 옳은 것을 모두 고른 것은?" 형식으로, 진술 4~6개(ㄱ~ㅂ)와
5지선다 조합(①~⑤)으로 구성됩니다. 단일 객관식보다 진술 단위 판단을 요구해
혼동쌍 대조 학습에 적합합니다 (`COMBO_STUDY_STRATEGY.md` §2-①).

```
입력  →  content/exams/cosmetic/문제은행/*.md ──(build:data)──> data/exams/*.js (choice)
        content/exams/cosmetic/참조자료/ref_md/과목N/{문서}/{문서}.md  (법령·고시 마크다운 — 과목 폴더가 귀속의 진실)
        content/exams/cosmetic/참조자료/원료/*.md              (큐레이션 원료 DB)

처리  →  build_combo_drills.js
          ├─ choice → combo 변환 (fact / answer 모드)
          ├─ 개념 재조합 (같은 교재 구간 L####의 진술 묶음)
          └─ 참조자료 원자 추출 → 멤버십·정의 문항 (ref_statements.js)

출력  →  data/exams/cosmetic/drills/combo_subjectN.js   (var COMBO_DRILLS_subjectN)
        data/exams/cosmetic/drills/combo_index.js       (var COMBO_INDEX — 과목별 문항 수)

        ※ 문제집 문서는 더 이상 MD 산출물이 아니다 — 앱의 "복수정답형 문제집"이
          src/combo-doc.js로 드릴 번들을 런타임 직렬화해 렌더링한다.
```

실행:

```powershell
node tools/build/build_combo_drills.js            # 생성 + 파일 쓰기
node tools/build/build_combo_drills.js --dry-run  # 검증만 (파일 미생성)
node tools/check/check_combo_pilot.js             # 생성 번들 무결성 감사
```

> **주의**: 생성물(`combo_*.js`)은 자동 생성 파일 — 직접 수정
> 금지. 소스(문제은행 MD, ref_md, 원료 DB)를 수정하고 재생성합니다.

## 2. 소스 ① — 문제은행 객관식 변환

`data/exams/subjectN.*.js`의 `choice` 문항을 진술 원자로 펼칩니다.
`blank`(단답형)와 이미 ㄱㄴㄷ 조합인 발문은 제외합니다.

### 2-1. 모드 판정

| 모드 | 조건 | truth 규칙 | 발문 |
|---|---|---|---|
| `fact` | 선지 ≥60%가 명제형(문장 종결 `다/음/함` 등) + 발문이 설명형·부정형 | 진술 **내용의 참/거짓**. 부정형 발문이면 정답 보기가 거짓 진술 | `다음 중 {주제}으로 옳은 것을 모두 고른 것은?` (항상 긍정 정규화) |
| `answer` | 회상형·분류형 선지(고유명사·수치) | **정답 여부** (극성 보존) | 원 발문 꼬리만 `…모두 고른 것은?`으로 교체 |

- `'위 ①②③ 모두'`류 메타 선지가 정답이면 원형 숫자 개수만큼 실질 선지를 참으로
  복구. 개수 불일치 시 신뢰 불가로 스킵하고 오류 집계.
- 자기참조 선지(①②③ 포함 텍스트)는 진술에서 제외.
- 발문 변환 불가 꼬리(`~하는가?` 등)는 원형 유지 + `— 해당하는 것을 모두 고르시오.` 부기.

### 2-2. 산출 필드

- `conceptId` = 해설의 첫 교재 라인(`L####`) — 같은 구간의 진술을 개념 클러스터로
  묶는 키. 교재 근거 없으면 `q:{문항id}` 폴백 (재조합 재료로는 미사용).
- `id` = `stableId(문항id)` — 재생성 순서와 무관하게 안정.
- `citation` = 해설의 `교재: Lxxxx`·법령 조문 추출. 없으면 `과목N 문제은행 Qn`.
- `explain` = 원본 해설에서 `정답: ②` 라인 제거한 정제본.
- 태그: `자동변환` + `명제판정`/`정답판정` + `inferTags` 자동 태그.

### 2-3. 개념 재조합 (`cluster:`)

단일 MCQ 변환만으로는 정답이 구조상 1개 — 같은 교재 구간(`conceptId`)의
fact 진술을 모아 **참 2~3 + 거짓 2~3**의 진짜 복수정답 문항을 추가 생성합니다.

- 진술 `sid`는 원본 것을 재사용 → 진술 단위 오답 통계·SM-2 이력 유지.
- 근접 중복(`nearDup`: 정규화 키 부분문자열·공통 접두 ≥60%) 쌍은 같은 문항에 배치 안 함.
- 발문은 `다음 설명 중 옳은 것을 모두 고른 것은?` 고정 — 챕터 라벨은 입자가 커서
  발문-진술 부조화를 낳으므로 사용 안 함.
- `derivedFrom: cluster:{L####}`로 식별.

## 3. 소스 ② — 참조자료 원문 추출 (`ref:`)

`ref_statements.js`가 `content/exams/cosmetic/참조자료/ref_md`의 법령·고시 마크다운에서
검증 원자(atom)를 추출합니다. 법령 텍스트는 구조가 참/거짓을 보장합니다.

### 3-1. 추출 원자

| 원자 | 패턴 | 참/거짓 구성 |
|---|---|---|
| `def` 정의조항 | `"X"이란/은/는 …을 말한다` | 참=원문, 거짓=같은 조의 다른 용어 정의와 교차 결합 |
| `enum` 조문 열거 | `다음 각 호/목` + `1.`/`가.` 항목 | 참=목록 멤버, 거짓=**다른 조** 목록 멤버 |
| `enum` 연번 표 | `연번` 단독줄 + 첫 셀 이름 | 참=표 이름, 거짓=다른 표의 이름 |
| `enum` MD 표 | 정상 `\| 표 \|`의 이름 열 | 참=표 이름, 거짓=다른 표의 이름 |
| `enum` 별표 계층 | `가. 카테고리` + `N)` 멤버 | 참=카테고리 멤버, 거짓=다른 목록 멤버 |
| `enum` 원료 큐레이션 | `참조자료/원료/*.md` 섹션·전체 표 (§4) | 참=카테고리 멤버, 거짓=다른 목록 멤버 (같은 파일 멤버는 배제) |
| `enum` 과목 노트 | `참조자료/과목N/N.*.md` 표의 이름 열 (§3-6) | 참=표 멤버, 거짓=다른 목록 멤버 |

### 3-2. 발문 규칙

멤버십을 명시해야 오답이 거짓이 됩니다.

- 인용 주제 있음(`topicSrc:'quote'`): `다음 중 {주제}에 해당하는 것을 모두 고른 것은?`
- 조문만 있음: `다음 중 「문서」제N조의 규정에 해당하는 것을 모두 고른 것은?`
- 주제도 조문도 없는 표 덤프 목록은 **생성 제외** — `「문서」의 규정에 해당` 발문은
  멤버십이 무엇인지 묻지 못해 무의미.

### 3-3. 품질 게이트 (`memberOk` + `isSentence`)

정답 멤버와 오답 풀 **모두**에 동일 필터 적용:

- 길이 4~140자, 한글 ≥40%, 균형 괄호·따옴표
- 제외: 포괄조항(`그 밖에`·`기타`), 특수기호(`◎◦※→`), 연속 공백, `,·-/` 종료,
  조사·연결어미 시작/종료 조각(`를 나타낸다`, `무기설파이트 및`), 항목 마커
  (`가.`·`제N조`·`1호`), 단자 접두(`어 지정된`), 의문문(`?` 포함), 표 헤더어
  (`구분`·`현황`·`품목명` 등), PDF 푸터 워터마크(`법제처·국가법령정보센터`)
- 괄호 헤딩 접두 `(피험자 선정) 피험자는…` 제거 — 단 `(1R,2S)-` 같은 IUPAC
  입체화학명은 접두가 한글이 아니므로 보존
- `isSentence`: 문장형(절차·규정 문장, `는가?`/`는지`/`하여` 종료 포함)과
  이름형(화학명) 멤버를 **멤버 단위**로 판정해 오답 풀을 분리 — 이름↔문장 혼합은
  길이만으로 정답이 들통남

### 3-4. 중복·모호성 방어

- 같은 문서+조문의 형제 목록 멤버는 모든 오답 풀(same/wide/anyPool)에서 배제
  (문서·조문 수준 멤버십 발문에 실제 해당할 수 있음)
- 목록 간 ≥3개 멤버 겹침 → 그 목록 전체 멤버를 오답 풀에서 배제
- 이미 처리한 목록과 ≥60% 겹치는 목록은 중복 문서본으로 스킵
  (캡으로 건너뛴 큐레이션 목록도 등록 — ref_md 중복본 재생성 방지)
- 오답 풀이 과목 내에서 부족하면 전 과목 풀로 확장 (알레르기 성분↔색소 교차)

### 3-5. 과목 귀속과 cap

ref_md는 `ref_md/과목N/{문서}/{문서}.md` 과목 폴더 구조이며, `extractRefAtoms`가
**물리 폴더를 귀속의 진실**로 사용한다. `DOC_SUBJECT_RULES`(문서명 → 과목)는
평탄 디렉터리 잔존 시의 후진 처리 및 노트·PDF 분류에 쓰인다: 법·시행규칙
본문 → 1, 개인정보 → 1,
`유통안전관리` → 3(안전기준 규칙보다 선행), 안전기준·CGMP·KFCC·색소 → 2,
주의사항·알레르기 → 4. `_구`로 끝나는 ref_md 디렉터리는 구(舊)버전 고시로
**추출 제외** — 개정 전 규정이 정답으로 출제되는 것을 방지.

시행규칙 별표는 법령 출처가 아닌 **내용 도메인**으로 귀속:
`별표1`(품질관리기준) → 2, `별표2/4/5/6`(책임판매안전·포장표시·표시광고·
위해화장품) → 3, `별표3`(사용시주의사항) → 4(주의사항 규칙과 동일),
`별표7/9`(행정처분·수수료)와 미지정 별표 → 1. `references.json`의
과목별 목록·물리 폴더(`참조자료/과목N/`)도 동일 기준으로 정렬됨.

검증: `npm run check:refsubjects` — 문제은행·교재의 `ref_md/` 인용 링크를
과목별 득표로 집계해 `DOC_SUBJECT_RULES` 귀속과 대조. 다수 인용 과목이 규칙과
다르고 ≥3표·규칙 과목의 2배 이상이면 '불일치'로 보고(`--strict` 시 exit 1).
법률·시행규칙·안전기준·CGMP 같은 모체 문서는 다과목 인용이 본질적이라
불일치 = 규칙 오류가 아니라 재분류 검토 신호로 해석한다.

`REF_COMBO_CAP = { 1: 35, 2: 92, 3: 40, 4: 150 }` — 목표 구성치까지 보충하는 상한.
과목3은 ref_md 원문 소스가 없어 과목 노트(safety 노트)만 사용.

### 3-6. 과목 노트 표 (`note|`)

법령 원문이 없는 영역(과목3 안전관리·과목4 피부생리·관능평가 등)은
`참조자료/과목N/`의 번호 있는 챕터 노트(`N.*.md`, `Nb.*.md` — `과목N_핵심*`
파일 제외)에서 표 멤버십을 추출합니다 (`extractNoteAtoms`).

- **멤버 열**: 엔티티 헤더(`NOTE_MEMBER_COL_RE`: 세포·기구·증상·원료 등) →
  1열 → 이름형 점수 최고 열 순으로 선택
- **전치 표**: 1열 헤더가 범용어(`NOTE_GENERIC_HDR_RE`: 구분·증상·방법 등)이고
  2열~이 이름형이면 **헤더가 멤버** (`| 구분 | 각질층 | 투명층 |` → 각질층/투명층)
- **주제**: 표 직전 헤딩 — `cleanNoteHeading`이 번호·①·이모지·`기출`·
  `비교표/정리` 꼬리를 제거. 무주제·무의미 주제(`핵심 용어`·`용어의 정의` 등
  `NOTE_BAD_TOPIC_RE`)는 스킵
- **셀 정제**: `**`·`<br>`·`<sup>`·`기출` 마커·선행 원형문자(`㉠㉡①`) 제거
- **처리 순서**: 큐레이션 → ref_md 원문 → 노트. cap 과목(1·2)에서 노트가
  원문 문항 슬롯을 잡지 않도록 노트는 항상 마지막
- 한계: 노트는 편집본이라 주제↔멤버 의미 정합이 법령보다 낮음 —
  `derivedFrom: ref:note|…`으로 식별해 검수 가능

## 4. 소스 ③ — 원료 큐레이션 DB (`원료|`)

`content/exams/cosmetic/참조자료/원료/`의 수작업 정제 파일은 PDF 변환본보다 품질이 높은
**권위 소스**입니다 (`INGREDIENT_FILES` 스펙).

| 파일 | docShort | 추출 목록 | 파일별 상한 |
|---|---|---|---|
| `banned_ingredients.md` | 원료DB 별표1 사용불가원료 | Chapter01 전체 표(사용불가 원료) + `### N.` 카테고리 섹션 | 24 |
| `restricted_ingredients.md` | 원료DB 별표2 사용제한원료 | `## (N)` 섹션(보존제·자외선차단 등) + 전체 합집합 | 18 |
| `approved_ingredients.md` | 원료DB 일반 원료 | `sectionAllow` 도메인 섹션만 (수성·유성·보존제·기능성·알레르기 등) | 14 |

특수 규칙:

- **우선 처리**: `curated` 원자를 목록 처리 선두에 배치 → ref_md의 같은 표
  중복본이 60% 겹침 규칙으로 자동 탈락. 큐레이션본의 발문·멤버가 채택됨
- **총량 제한**: 큐레이션 문항은 과목 cap의 60% + 파일별 상한 — 원료 멤버십만으로
  채워지는 단조로움을 막고 CGMP·색소·기능성 문항에 슬롯 확보
- **같은 파일 배제**: 별표1 카테고리 문항의 오답에 같은 파일의 다른 카테고리
  원료를 쓰지 않음 — "사용불가 원료를 아닌 것으로 표기"하는 모순 방지
- 섹션 제목은 번호·꼬리 괄호 주석(`(반드시 암기)` 등)을 제거해 발문화
  → `다음 중 사용불가 원료(별표1)의 중금속 및 유해 화학물질에 해당하는 것을…`

## 5. 검증과 산출

### 5-1. 문항 검증

모든 생성 문항은 `src/questions.js`의 `validateQuestion` + `deriveComboAnswer`를
통과해야 합니다: 참 진술 ≥2, 진술 ≥4, 조합 선지 일관성. 실패 문항은 제외하고
오류로 집계·출력됩니다.

### 5-2. 산출물

- `data/exams/cosmetic/drills/combo_subjectN.js` — `var COMBO_DRILLS_subjectN = [...]`
- `data/exams/cosmetic/drills/combo_index.js` — 과목별 문항 수(`combo_pilot.js` 수작업 문항 합산)
- 문제집 문서(뷰어 "복수정답형 문제집")는 산출물이 아니라 `src/combo-doc.js`가

## 7. 품질 감사 체크리스트

재생성 후 확인할 것:

1. `node tools/check/check_combo_pilot.js` — 정답 분포·스키마 무결성
2. `npm.cmd run audit:combo` — 생성 번들 품질 감사 (`tools/check/audit_combo.js`):
   스키마·정답 유일성 재검증, 동일 진술집합 중복 문항, 모순 의심 쌍(동일 텍스트·상반 truth),
   진술 절단 의심(조사·연결어미 종결), '모두' 퇴화/위반 옵션, 정답 위치 편향(>30%),
   과목별·생성 경로별(bank/cluster/ref:*) 통계. 오류 시 exit 1, `--strict`는 경고도 실패 처리.
   상세 리포트는 `combo_audit_report.json` (gitignore 대상)
   - **회귀 가드**: `combo_baseline.json`(커밋됨)과 과목별 문항 수 비교 — 10% 감소 시 경고, 30% 시 오류.
     의도된 생성량 변경 후 `--update-baseline`으로 갱신
   - **검수 큐**: cluster·ref:note 경로 + 경고 문항을 `combo_review_queue.md`로 출력.
     불량 문항은 id를 `<contentRoot>/combo_blocklist.json`의 `ids`(또는 `derivedFromPrefixes`)에
     등록하면 다음 빌드에서 제외됨. 검수 완료(양호)는 `approved`에 등록 → 큐에서 제외되어
     미검토 문항만 남는다
   - **배포 게이트**: `npm run deploy`가 git 검사 후 `audit:combo`를 자동 실행 —
     오류 시 배포 차단 (경고는 통과)
   - **모순 휴리스틱**: 같은 술어·다른 수치를 둘 다 참으로 표기(numConflict),
     극성 반쌍(있다/없다·가능/불가 등) 동일 truth(negConflict) — 모순 의심 경고
   - **런타임 이상 탐지**: 판정 5회+ 누적 후 오판율 ≥80%인 진술은 `getAnomalousStatements()`가
     '이상 의심'으로 표시 — 취약 진술 목록에서 배지로 노출 (진술 표현·진위 검수 후보).
     앱 백업 JSON을 `audit:combo --anomalies <backup.json>`에 넘기면 이상 진술의
     **포함 문항이 검수 큐에 자동 추가**됨 (sid → 문항 역매핑)
   - **골든 테스트**: `tests/unit/combo-transform.test.js`가 변환 규칙(극성 역전·'모두' 복구·
     스킵 조건·발문 변환)을 고정 — 변환 로직 변경 시 회귀 감지
3. 같은 문항 정오답 텍스트 중복 — 정규화 키 비교로 0이어야 함
4. 큐레이션 교차 오류 — 별표1 문항 오답이 `banned_ingredients.md` 멤버이면 오류
5. 잔재 스캔 — `?`·`법제처`·단자 접두·조사 종료 진술
6. 발문 분포 — 한 발문이 과도하게 반복되지 않는지, 무의미 토픽(`명칭` 등) 없는지
7. `npm.cmd test` · `check:parser` · `check:imports` · `verify:assets`

## 8. 다른 과목·시험 콘텐츠에의 재사용성

### 8-1. 도메인 무관 — 그대로 동작

| 로직 | 이유 |
|---|---|
| choice→combo 변환 (fact/answer) | 발문 꼬리 패턴·명제 판정은 한국어 문법 수준 규칙 — `data/exams/*.js`만 있으면 동작 |
| 개념 재조합 (`cluster:`) | `교재: L####` 인용 관례에만 의존 — 도메인 무관 |
| 멀티시험 라우팅 | `getExamTargets`가 `exams.json`을 순회하고 과목 매핑은 `manifest.json`에서 파생 |
| 법령 추출 패턴 | `제N조(제목)`·`다음 각 호/목`·`"X"이란…말한다` — 한국 법령 문서 공통 형식 |
| `memberOk`/`isSentence` 필터 | 조각·워터마크·문장형 판정 — 언어 수준 규칙 |

### 8-2. 도메인 하드코딩 — 새 과목/시험이면 채워야 함

| 위치 | 역할 | 미설정 시 동작 |
|---|---|---|
| `DOC_SUBJECT_RULES` (`ref_statements.js`) | 문서명 → 과목 귀속 | 규칙 미일치 → `docSubject` null → 해당 문서 원자 미생성 |
| `INGREDIENT_FILES` (`ref_statements.js`) | 원료 DB 파일·섹션 스펙 | `원료/` 폴더 없으면 조용히 스킵 |
| `TABLE_TOPICS` (`ref_statements.js`) | 표 문서별 발문 주제 | 주제 없으면 조문/문서명 발문, 둘 다 없으면 목록 스킵 |
| `REF_COMBO_CAP` (`build_combo_drills.js`) | 과목별 참조자료 상한 | 과목 번호 미정의 → cap 0 → 참조자료 문항 0개 (안전한 기본값) |
| `cat` 목록 추출 한정 (`/주의사항\|알레르기/`) | 계층 목록 추출 대상 문서 | 미일치 문서의 cat 목록은 추출 안 함 |

### 8-3. 경우별 판정

- **법 개정·문제은행 추가 등 기존 시험 콘텐츠 갱신** — 완전 자동.
  `build:data` → `build_combo_drills.js` 재실행으로 끝. 정규식이 `제N조`·
  `다음 각 호` 같은 법령 형식을 보므로 문서 내용이 바뀌어도 무방.
- **같은 도메인의 ref_md 문서 추가** — 문서명이 `DOC_SUBJECT_RULES`에 걸리면
  자동 흡수. 안 걸리면 규칙 한 줄 추가.
- **다른 자격시험 추가** — 변환·재조합은 무수정 동작. 참조자료 문항을 원하면
  ① `content/exams/<id>/참조자료/ref_md/` 배치 ② `DOC_SUBJECT_RULES`에 새
  법령명→과목 규칙 추가 ③ 필요 시 자체 큐레이션 파일 + `INGREDIENT_FILES` 스펙
  ④ `REF_COMBO_CAP` 조정 — 4개 테이블만 채우면 된다.
  파이프라인 골격(변환·검증·출력)은 시험 독립적이고, 도메인 결합부는 규칙
  테이블에 격리돼 있다. 규칙 미설정 실패는 조용히 0건으로 처리되므로
  오동작 위험은 낮다.

## 9. 알려진 한계

- 과목3·4는 법령 밖 영역 — ref_md 소스가 없어 과목 노트 표가 참조자료 문항의
  주 소스 (§3-6). 노트는 편집본이라 `ref:note|…` 문항은 검수 권장
- 개념 재조합 문항은 다른 문항 진술 간 의미 모순을 기계 검출하지 못함 —
  소수 문항이므로 출제 검수 권장 (`derivedFrom: cluster:…`로 식별)
- PDF 변환본(ref_md) 표는 셀 절단·공백 소실 잔재가 남을 수 있음 —
  원료 문항은 항상 큐레이션 DB를 우선하고, 신규 표 목록 추가 시 생성 샘플 검수 필수
