## 1. 설계 원칙

| 원칙 | 내용 | 근거 |
|------|------|------|
| **Local-First + Optional Cloud** | 기본은 서버/DB/인증 없는 순수 정적 프론트엔드, 클라우드 계정·동기화는 "없어도 동작하는" 선택 계층(Supabase lazy-load)으로 추가 가능 | 개인 학습 도구 특성상 운영 비용·복잡성 제거, 무료 호스팅(Vercel) 활용하면서 멀티기기 동기화 경로 확보 |
| **Vanilla First** | React/Vue 등 프레임워크 미사용, 순수 HTML/CSS/JS (ESM) | 빌드 스텝 제거, 장기 유지보수 시 프레임워크 종속성 리스크 제거, 번들 크기 최소화 |
| **Offline-Capable PWA** | Service Worker로 App Shell + 학습 데이터 캐시 | 이동 중/무인터넷 환경에서도 학습 가능, 설치형 PWA로 홈 화면 추가 |
| **Mobile-First Responsive** | 모바일 하단 탭 바 ↔ 데스크톱 사이드바 적응형 | 실제 사용자 대부분이 스마트폰 접속 |
| **Content-Agnostic** | `manifest.json`을 SSOT로 사용, 교재 전체 교체 시 소스 수정 최소화 | 콘텐츠와 코드의 분리, 재사용성 극대화 |

## 2. 시스템 아키텍처

### 2.1 계층 구조

```
Browser (Client)
├── Presentation Layer    — index.html (App Shell) + CSS (디자인 시스템)
├── Application Layer     — app.js (초기화·라우팅·이벤트 위임)
│   ├── State Management  — state.js (전역 상태, localStorage 영속성)
│   ├── Data Loader       — data-loader.js (온디맨드 과목 로딩)
│   ├── Parsers           — textbook-parser.js, markdown-parser.js
│   ├── View Controllers  — views/*.js (각 기능별 뷰 모듈)
│   └── Security          — sanitize.js (XSS 방어)
├── Data Layer            — registry.js (빌드 생성), ingredients_data.js
├── Persistence Layer     — localStorage (학습 진행) + Cache Storage (SW)
└── Service Worker        — sw.js (오프라인 캐싱, 7단계 분기 전략)
```

### 2.2 호스팅

| 항목 | 방안 |
|------|------|
| 정적 호스팅 | Vercel 무료 티어 (CDN, 커스텀 도메인, 보안 헤더) |
| 대용량 미디어 | 외부 CDN (오디오북 등, SW 캐시 제외) |
| 파일 크기 제약 | 100MB/파일 — 대용량 콘텐츠는 런타임 fetch + MD 변환으로 회피 |

### 2.3 의존성 최소화

| 항목 | 방안 |
|------|------|
| 런타임 라이브러리 | 없음 (차트, 다이어그램 모두 자체 구현 또는 온디맨드) |
| 온디맨드 라이브러리 | Mermaid.js (다이어그램 블록이 있을 때만 동적 로드) |
| 폰트/아이콘 | 자체 호스팅 (오프라인 지원) |
| 개발 의존성 | Vitest + jsdom (테스트), Node.js (빌드 도구) |

## 7. 콘텐츠 저작 규칙

### 7.1 디렉토리 구조 (템플릿)

```
content/
├── manifest.json              ← SSOT: 과목/단원/파일 정의
├── 교재/
│   ├── subject1/              ← 과목 1 폴더 (key와 매칭)
│   │   ├── 1과목_제목_표준형.md
│   │   └── 1과목_제목_이야기형.md   ← 선택
│   ├── subject2/
│   └── ...
├── 문제은행/
│   ├── 과목1_문제은행.md
│   └── ...
├── 참조자료/                   ← 학습 보조 자료
│   ├── 공통/                   ← 공통 참조자료
│   ├── 법령원문/               ← 법령 원문 (해당 시험에 법령이 있는 경우)
│   ├── 과목1/                  ← 과목별 참조자료
│   └── 원료/                   ← 분야 특화 자료 (성분 등)
└── 학습안내서.md
```

### 7.2 교재 본문 Markdown 규칙

| 헤더 | 용도 | 파서 동작 |
|------|------|-----------|
| `#` | 교재 제목 (파일당 1개) | `chapterTitle` 추출 |
| `##` | 섹션 (단원/주제) | 카드 `category`, 교재 리더 섹션 분할 |
| `###` | 서브 섹션 | 참조용, 카드 추출에 영향 없음 |

### 7.3 카드 추출 규칙

- **표**: 첫 번째 열 = 용어(term), 두 번째 열 = 정의(definition)
- **리스트**: `🔖기출` 또는 `📌중요` 마커가 있는 항목만 카드로 추출
- **자동 제외**: 용어 3자 이하/50자 초과, 정의 10자 이하, 범용 표현, 숫자만 있는 용어

### 7.4 퀴즈 자동 생성 규칙

1. `**볼드**` 텍스트 → 빈칸 채우기 퀴즈
2. 숫자+단위 패턴 → 빈칸 채우기 퀴즈
3. 둘 다 없음 → 용어 맞추기 퀴즈 (정의 → 용어)

### 7.5 학습 보조 요소 (권장)

각 `##` 섹션에 배치 권장:

| 요소 | 형식 | 효과 |
|------|------|------|
| 학습 가이드 | `> 📋 출제 빔도: ★★★ 예상 소요: 60분 핵심 키워드: ...` | 학습 방향 설정 |
| 한 줄 핵심 | `> ### 🎯 한 줄 핵심: ...` | 섹션 요약 |
| 출처 표기 | `> 📌 출처: 법령 제N조 | 참조 PDF: ...` | 근거 명시 |
| 비교표 | `| 구분 | A | B | C |` | 개념 대조 |
| 확인문제 | `> 📝 Q. ... (정답: ...)` | 즉시 확인 |

### 7.6 Mermaid 다이어그램 (선택)

교재 MD에 ```` ```mermaid ```` 코드블록으로 작성하면 온디맨드 로드 + 자동 렌더링됩니다. 타입은 `src/mermaid-utils.js`가 자동 감지합니다.

| 타입 | 용도 | 문법 | CSS 클래스 |
|------|------|------|------------|
| mindmap | 계층 구조 시각화 | `mindmap` + 들여쓰기 (root 1 space, 각 레벨 +1) | `mermaid-mindmap` |
| flowchart | 절차/흐름 시각화 | `flowchart TD` + 노드/화살표 | `mermaid-flowchart` |
| sequenceDiagram | 상호작용 순서 (신고→심사→승인) | `sequenceDiagram` + participant/메시지 | `mermaid-other` |
| gantt | 일정/타임라인 (시험 준비, 법령 시행) | `gantt` + dateFormat/section | `mermaid-other` |
| pie | 비율 시각화 (출제 비율, 배점) | `pie title ...` + 데이터 | `mermaid-other` |
| timeline | 연혁/제도 변천 | `timeline` + 연도/이벤트 | `mermaid-other` |
| stateDiagram-v2 | 상태 변화 (허가 절차, 제품 수명) | `stateDiagram-v2` + 상태/전이 | `mermaid-other` |
| gitGraph | 개정 이력 (법령 변천) | `gitGraph` + commit/branch | `mermaid-other` |
| quadrantChart | 2축 매트릭스 (효능 vs 위험도) | `quadrantChart` + 축/데이터 | `mermaid-other` |
| classDiagram | 클래스/구조 관계 | `classDiagram` + 클래스 정의 | `mermaid-other` |
| erDiagram | 엔티티 관계 (법령 간 참조) | `erDiagram` + 엔티티/관계 | `mermaid-other` |
| sankey | 흐름/분배 (원료→배합→제품) | `sankey` + 소스/타겟/값 | `mermaid-other` |

> **스타일 분리**: flowchart만 `lineWidth: 1` 등 세부 themeVariables 적용, mindmap은 기본 스타일 유지, 기타 타입은 Mermaid 기본 테마 + 텍스트 대비 보정만 적용

### 7.7 이야기형 교재 (선택)

- 파일명 규칙: `{기본파일명}_이야기형.md`
- 동일한 `##` 섹션 구조 유지
- 서사는 `### 📖` 서브헤더 아래에 배치 (카드/퀴즈 추출에 영향 없음)
- 파일이 없으면 자동으로 기본 교재 파일 표시

### 9.1 콘텐츠 준비

- [ ] `manifest.json`의 `subjects[].key`/`dir`/`file` 경로가 실제 파일 위치와 일치하는가?
- [ ] `manifest.json`의 `exams[].subject`가 `subjects[].key`와 매칭되는가?
- [ ] `manifest.json`의 `uiText`가 새 자격증명/과목명에 맞게 수정되었는가?
- [ ] 교재 MD 파일의 `#` 헤더가 파일당 1개인가?
- [ ] 카드 추출을 원하지 않는 `##` 섹션에 제외 마커(`🧭`, `📊` 등)가 있는가?
- [ ] 교재 마크다운 작성 규칙(표 구조·마커·정답 섹션 위치 등)은 TEXTBOOK_AUTHORING_GUIDE의 최종 체크리스트를 따르는가?

- [ ] `references.json`의 참조자료 매핑이 새 교재의 법령/자료에 맞는가? (`pdf-registry.js`·`law-links.js`는 `build:pdf-registry` 생성물 — 직접 편집 금지)
