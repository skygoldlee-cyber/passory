# Formula OS 실무 도구 확장 설계 — FO-57~63

> **문서 ID**: DOC-DSN-15
> **관련 SPEC ID**: `FO-57`(LOT 역추적) · `FO-58`(판매내역서) · `FO-59`(이상사례) · `FO-60`(동의서) · `FO-61`(재고 차감) · `FO-62`(리마인더) · `FO-63`(보고서 이력) · 선행 `FO-56`(종합 보고서) · `FO-16`(배치) · `FO-18`(원료 장부) · `FO-33`/`FO-34`(사업 유형)
> 상태: 승인

## 1. 배경·목적

종합 점검 보고서(FO-56)가 "사전 점검"을 커버한다면, 실무에는 사후 증적·운영 편의
기능이 남아 있다. 본 문서는 7개 실무 기능의 스키마·게이트·진입점·데이터 정합성
규칙을 정의한다. 공통 원칙은 FO-56과 동일하다 — localStorage가 1차 저장소,
fp-doc 인쇄가 문서 산출물, `bizVisible`/`BIZ_PANELS` 게이트 재사용, 사용자
데이터는 전면 `esc()`.

## 3. 기능별 결정

### 3.1 FO-57 LOT 역추적

- 조회: `findBatchesByMaterial(materialId, name)` — 배치 `materialLots[]`에서
  materialId 우선 매칭, 원료명을 보조 매칭으로 사용한다. 장부 항목이 삭제돼도
  배치 스냅샷의 name이 남아 있으므로 name 폴백이 추적 연속성을 지킨다.
- 결과는 원료 패널 내 `#material-trace-result`에 표시 — 배치번호·처방·고객·
  조제일·인도일 + 상세 이동. [추적 목록 인쇄]는 `buildRecallListHtml` 사용.
- 제한: LOT 미선택 배치(장부 미등록 원료로 조제)는 추적에 나타나지 않는다 —
  출력 면책 문구에 명시.

### 3.2 FO-58 판매내역서

- `deliveredAt`이 기록된 배치만 대상 — 인도일 내림차순 정렬.
- 문서: 인도일·배치번호·제품·고객·내용량·비고 + 작성자·확인일 서명란.
- 필터는 제공하지 않는다 — 목록의 기존 필터(QC·인도 여부)와 역할이 달라
  "인도 완료 전체"를 한 번에 출력하는 증적 문서로 단순화한다.

### 3.3 FO-59 이상사례 기록

- 스키마: `{id:'adv_', occurredAt, customerId, customerName, product, symptoms,
  action, reportedAt, notes, createdAt, updatedAt}` — 필수는 발생일·증상.
- `reportedAt`은 관계기관(식약처 등) 보고일 — 미보고는 빈 문자열이며 목록에
  '미보고'로 표기해 보고 공백 자체가 가시화된다.
- Free 한도 30건(`ADVERSE_LIMIT_FREE`) — 다른 스토어와 동일 패턴.
- 게이트: BIZ_PANELS 미선언 → 전 유형 공통 (이상사례는 유형 무관 의무).
- 보고서 연계: `collectAdverse()`가 종합 보고서에 고객 섹션 바로 뒤에 삽입 —
  소비자 관련 증적을 한 덩어리로 묶는다.

### 3.4 FO-60 고객 안내·동의서

- 고객 카드의 알레르기 이력 + 해당 고객 최신 배치(있으면 제품·배치 표기)로
  서명용 고지 문서 생성. `buildConsentHtml` 사용.
- 안내 문구는 일반 고지(타인 사용 금지·이상 증상 대응·보관법·이상사례 기록
  안내)로 고정 — 처방별 성분 원문은 포함하지 않는다 (전성분표는 라벨의 역할).

### 3.5 FO-61 재고 자동 차감

- 차감 시점: **신규 배치 저장에만** — 보정(update)은 감사 정합상 미차감.
  - 보정 모드에서 수량을 다시 차감하면 중복 차감되고, 복원 로직(차감 롤백
    후 재차감)은 LOT 변경·부분 실패 시 원자성을 보장할 수 없다.
  - 보정으로 총량을 크게 바꾼 경우의 차이분은 수동 정정으로 처리한다 —
    화면 안내보다 자동화의 실패 모드가 더 크다고 판단.
- 소요량: 선택된 `materialLots` 각각에 대해 `처방 ingredient.concentration ×
  targetVolume / 100`. 농도·총량 미기재 원료는 건너뛴다(skipped 목록).
- 잔량 처리: `qty` 미기재 원료는 건너뛰고, 차감 결과가 음수면 0으로 바닥내며
  `shortages`로 반환 — 저장 차단이 아닌 토스트 경고 (기록 우선 원칙).
- 소진 표시: `stockStatus()`가 'out'이면 장부 카드에 '소진' 배지 + 배치 폼
  LOT 옵션을 `disabled`(기존 배치가 선택한 LOT는 복원 위해 유지).

### 3.6 FO-62 점검 주기 리마인더

- 트리거: `initFormulaView()` — 활성 세트 키의 `{updatedAt}`이 30일 경과.
- 미시작(키 자체 없음)은 알리지 않는다 — 신규 사용자에게 즉시 경고를 띄우는
  것은 잡음이며, '미실시'는 보고서의 '기록 없음' 표기가 이미 증적 역할.
- 표시: 법규 준수 허브 카드 설명란에 `재점검 권장 — 마지막 점검 N일 전` 배지.

### 3.7 FO-63 보고서 출력 이력

- 내용: `{at, bizId, bizLabel, setLabel, done, total, sections}` — 메타데이터만.
  본문(고객 개인정보)은 저장하지 않는다 — FO-56의 미저장 원칙을 이력에서도
  유지하면서 "지난번 대비 진척" 확인을 가능하게 하는 최소 범위.
- 기록 시점: `auditPrintReport()`가 수집 직후 `recordAuditLog()` 호출 —
  출력 취소(print 다이얼로그 취소)도 '생성'으로 기록된다. 이력은 감사 증적이
  아닌 진척 표시 목적이므로 허용 오차.
- 보존: 최대 20건(FIFO), 표시는 법규 준수 패널 '보고서 출력 이력' 섹션에 최근 5건.
- 백업·초기화: `BACKUP_KEYS` 등록 — 기기 간 이력 유지, Reset 시 함께 제거.

## 4. 신규 영속 키

| 키 | 내용 | 상한 | 백업 |

## 5. 진입점·게이트

- 허브 카드(이상사례)는 분석·법규 도구 그룹에 배치 — data-biz 미선언으로 전 유형 노출.
- 서브내비에 '이상사례' 칩 추가 — 패널 간 이동 일관성.
- 신규 지연 로더 `adverse` + 기존 로더(material·batch·customer)에 핸들러 추가.

## 6. 테스트 전략

- 유닛: `adverse-store` CRUD·정제·한도, `deductStock` 차감·바닥·부족·건너뜀,
  `findBatchesByMaterial` 매칭, `recordAuditLog` 20건 상한, 수집기 adverse 섹션.
- DOM: 추적 렌더·인쇄, 판매내역서 필터링, 동의서 생성, 이상사례 패널 CRUD,
  리마인더 배지(30일 경과/미시작 억제), 이력 표시.

## 7. 비목표

- 재고 차감의 보정·삭제 롤백 — §3.5 결정에 따라 수동 정정.
- 이상사례의 관계기관 전자 보고 연동 — 기록 관리까지만.
- 보고서 본문 스냅샷 저장 — FO-56 결정 유지, 이력은 메타데이터만.
