## 2. 단계별 상세 분석

### 2.1 교재 읽기 → 핵심 개념 추출: ✅ 완전 연결 (100%)

**구현 파일**: `src/textbook-parser.js` (638 lines)

`parseMarkdownFile()` 함수가 교재 Markdown에서 카드와 퀴즈를 자동 추출합니다.

**핵심 로직**:

- 카드 ID: `sha256(subjectKey|chapterKey|term)` — 기기·재빌드 간 안정적
- 카드 타입 분류: `classifyCardType()` — 8가지 타입 (처벌/금지/예외/숫자/요건/비교/절차/개념)
- 중요도 산출: `scoreCard()` — 0-100점 (시험중요도 30% + 암기필요도 25% + 숫자/조건성 15% + 기출관련성 15% + 카드적합성 10% + 반복학습가치 5%)
- 난이도 분류: `determineDifficulty()` — easy/medium/hard
- 퀴즈 품질 검사: `isValidQuiz()` — 정답 길이, 빈 질문 필터링

**파이프라인 연결성**: 교재 MD → 카드/퀴즈 자동 추출 → 빌드 번들 → 런타임 로드. 완전히 연결되어 있습니다.

> 참조: `src/textbook-parser.js` lines 164-180 (parseMarkdownFile), lines 59-77 (classifyCardType), lines 80-130 (scoreCard)

### 2.2 플래시카드 암기 → 문제 풀이: ✅ 완전 연결 (100%)

**구현 파일**: `src/views/flashcard.js` (156 lines)

플래시카드는 과목별 필터링, 난이도 필터, 셔플, 중요도 정렬을 지원합니다. "외웠어요"/"헷갈려요" 버튼으로 `memorizedCards`/`weakCards` Set에 기록됩니다.

**핵심 로직**:

- `loadFlashcards()`: 과목 데이터 로드 + 필터링 (keyOnly, difficulty, shuffle, importance 정렬)
- `renderFlashcard()`: 3D 플립 카드 렌더링, 외움/헷갈림 상태 표시
- 카드 타입 배지: 8가지 타입 시각적 구분
- 기출 마커: `isKey` 카드에 별 표시

퀴즈는 같은 교재에서 추출된 빈칸 채우기/객관식/OX 문제를 10문제 단위로 출제합니다.

> 참조: `src/views/flashcard.js` lines 20-49 (loadFlashcards), `src/views/quiz.js` lines 43-72 (startQuiz)

### 2.3 문제 풀이 → 오답 분석: ⚠️ 부분 연결 (30%)

#### 퀴즈 오답 처리

**구현 파일**: `src/views/quiz.js`


퀴즈 오답은 `state.quizResults`에 `correct: false`로 저장되지만, **`weakCards`에 추가되지 않습니다**. 오답 리뷰 화면에 표시만 됩니다.

> 참조: `src/views/quiz.js` lines 193-206

#### 모의고사 오답 처리

**구현 파일**: `src/views/exam-simulator.js`

```javascript
// 모의고사 오답은 weakCards에 추가됨
simState.wrongQuestions.push({ ...q, userAnswer: userAns });
const fakeCardId = `weak_sim_${q.id}`;
state.weakCards.add(fakeCardId);
```

모의고사 오답은 `weakCards`에 `weak_sim_*` ID로 추가되어 복습 노트에 연결됩니다.

> 참조: `src/views/exam-simulator.js` lines 477-484

#### 문제점

## 3. 파이프라인 연결성 매트릭스

| From → To | 연결 상태 | 비고 |
|-----------|----------|------|
| 교재 → 개념 추출 | ✅ 완전 | `textbook-parser.js` 자동 추출 |
| 개념 → 플래시카드 | ✅ 완전 | 같은 파서에서 동시 생성 |
| 개념 → 퀴즈 | ✅ 완전 | 같은 파서에서 동시 생성 |
| 카드 → SM-2 복습 | ✅ 완전 | 외움/헷갈림 → `updateCardSchedule` |
| 퀴즈 오답 → weakCards | ❌ 누락 | `quiz.js`는 `quizResults`에만 저장 |
| 모의고사 오답 → weakCards | ✅ 완전 | `weak_sim_*` ID로 추가 |
| weakCards → 대시보드 | ⚠️ 과목 단위 | 개념 단위 분석 없음 |
| SM-2 → 대시보드 | ✅ 완전 | `getDueCount()` 표시 |
| SM-2 → AI 추천 | ❌ 미연결 | 추천 로직에 통합 안 됨 |
| 오답 → 교재 섹션 | ❌ 미연결 | 오답에서 교재로 되돌아가기 없음 |
| 오답 → 관련 카드 | ❌ 미연결 | 오답 키워드 → 카드 매칭 없음 |
| 합격 예측 → 학습 추천 | ❌ 미연결 | 예측 결과가 추천에 영향 없음 |
| 모의고사 → 합격 예측 | ✅ 완전 | 성적 이력 기반 판정 |

### 연결성 통계

| 상태 | 개수 | 비율 |
|------|------|------|
| ✅ 완전 연결 | 6 | 46.2% |
| ⚠️ 부분 연결 | 1 | 7.7% |
| ❌ 미연결 | 6 | 46.2% |
| **총계** | **13** | **100%** |

## 5. 가장 끊어진 파이프라인 (우선 수정 필요)

### 5.1 퀴즈 오답 → weakCards 연결 누락

**심각도**: 🔴 높음

`quiz.js`가 모의고사와 달리 `weakCards`에 오답을 추가하지 않습니다.

```javascript
// 현재 (quiz.js): quizResults에만 저장
state.quizResults[currentQuiz.id] = { solved: true, correct: isCorrect };

// 모의고사 (exam-simulator.js): weakCards에도 추가
state.weakCards.add(`weak_sim_${q.id}`);
```

**영향**: 퀴즈 오답이 복습 노트에 누락되어, 사용자가 퀴즈에서 틀린 문제를 복습할 수 없습니다.

**수정 방향**: `quiz.js`의 `submitQuizAnswer()`와 `submitQuizChoiceAnswer()`에서 오답 시 `state.weakCards.add()` 호출 추가.

---

### 5.2 오답 → 재학습 콘텐츠 연결 없음

**심각도**: 🔴 높음

오답이 발생해도 관련 교재 섹션/카드/유사문제로 되돌아가는 경로가 없습니다. 사용자가 스스로 찾아야 합니다.

**영향**: "왜 틀렸는지"는 알려주지만 "무엇을 다시 공부해야 하는지"는 안 알려줌.

**수정 방향**:
1. 오답의 `quizId`에서 과목/챕터 추출
2. 같은 챕터의 교재 섹션으로 이동 링크 생성
3. 같은 챕터의 플래시카드 목록 추천
4. 같은 타입/태그의 유사 문제 추천

---

### 5.3 AI 학습 경로 추천 미구현

**심각도**: 🔴 높음

SM-2 복습 대기 + 정답률 + 미학습 챕터를 종합한 추천이 없습니다.

**영향**: 사용자가 "오늘 무엇을 공부해야 할지" 스스로 결정해야 함.

**수정 방향**:
1. SM-2 `getDueCards()` → 과목별 복습 대기 카드 수 산출
2. `quizResults` → 과목별 정답률 산출
3. `memorizedCards` → 과목/챕터별 암기율 산출 → 미학습 챕터 감지
4. 모의고사 성적 이력 → 과락 과목 감지
5. 우선순위 계산: 복습 대기 > 과락 보완 > 정답률 최저 > 미학습
6. "왜 이것을 공부해야 하는지" 이유와 함께 추천 카드 렌더링

---

### 5.4 시험 직전 집중 학습 미구현

**심각도**: 🟡 중간

D-Day, 학습 목표, 요약 노트가 없습니다.

**영향**: 시험 일정 관리 불가, 시험 직전 집중 학습 불가.

**수정 방향**:
1. 시험일 설정 UI + localStorage 저장
2. D-Day 카운트다운 대시보드 표시
3. 일일/주간 학습 목표 설정 (카드 수, 퀴즈 수, 학습 시간)
4. 목표 달성률 추적
5. 시험 직전 요약 노트 자동 생성 (외운 카드 + 오답 기반)

---

## 6. 결론 및 Phase 1 구현 우선순위

### 핵심 진단

> 현재 코드는 **개별 기능(교재, 카드, 퀴즈, 모의고사, SM-2)은 완성도가 높지만**,
> 핵심 루프의 **파이프라인 연결성이 부족**합니다.
> 특히 "오답 → 원인 분석 → 재학습 연결 → AI 추천" 구간이 완전히 끊겨 있습니다.

### 좋은 소식: 엔진은 다 있다, 배선만 남았다

> 가장 어려운 부분들은 이미 100% 완성되어 있습니다:
> - 교재 파싱 + 카드/퀴즈 자동 추출 (`textbook-parser.js`)
> - SM-2 간격 반복 알고리즘 (`spaced-repetition.js`)
> - 모의고사 100제 + 과락 판정 (`exam-simulator.js`)
> - 3단계 합격 예측 (`charts.js`)
>
> 남은 작업은 **새 엔진을 만드는 것이 아니라, 이미 있는 데이터를 연결하는 배선 작업**입니다.
> 1순위(퀴즈 오답 → weakCards)가 `add()` 한 줄 추가인 것이 그 증거입니다.
> 따라서 Phase 1은 "엔진 개발"이 아닌 "파이프라인 연결"로 접근해야 합니다.

### Phase 1 구현 우선순위

```
1순위: 퀴즈 오답 → weakCards 연결 (즉시 수정 가능, 공수 소)
   └── quiz.js에 state.weakCards.add() 추가

2순위: AI 맞춤 학습 경로 추천 (핵심 기능, 공수 중)
   ├── SM-2 복습 대기 + 정답률 + 미학습 챕터 종합
   ├── "왜 공부해야 하는지" 이유 표시
   └── 다단계 학습 경로 (복습 → 오답 → 신규)

3순위: 오답 분석 → 재학습 연결 (핵심 파이프라인, 공수 중-대)
   ├── 오답 원인 분류 — 1단계: 사용자 자가 태깅 UI (공수 소)
   │   └── 오답 발생 시 "암기 부족 / 개념 오해 / 계산 실수" 버튼 선택
   │   └── AI 자동 분류는 데이터 축적 후 2단계로 도입 (공수 대)
   ├── 오답 → 관련 교재 섹션 이동
   ├── 오답 → 관련 플래시카드 추천
   └── 오답 → 유사 문제 추천

4순위: 학습 목표 / D-Day (공수 중)
   ├── 시험일 설정 + D-Day 카운트다운
   ├── 일일/주간 학습 목표 설정
   └── 목표 달성률 추적
```

### 기대 효과

| 개선 항목 | 현재 | 개선 후 |
|----------|------|--------|
| 루프 완성도 | 50% | 85%+ |
| 파이프라인 연결 | 40% | 80%+ |
| 오답 → 재학습 | 0% | 100% |
| AI 추천 | 10% | 80%+ |
| 시험 일정 관리 | 0% | 100% |
